# robo_lab — Godot 4.7.2

[English version](README.en.md) · другая версия: ветка [`godot-4.1.1`](https://github.com/exdietolog/robo_lab/tree/godot-4.1.1)

Лабораторные работы по дисциплине «Программирование мехатронных и робототехнических систем» (МГТУ «СТАНКИН», кафедра робототехники и мехатроники). Все работы выполняются в движке **Godot** на языке **C#**: вы строите модель манипулятора, решаете для неё задачи кинематики и пишете программы движения.

Это ветка **`godot-4.7.2`**: все четыре лабораторные — чистые шаблоны (без решений) для **Godot 4.7.2 .NET / .NET 8.0** (`net8.0`). Те же лабораторные для Godot 4.1.1 — в ветке [`godot-4.1.1`](https://github.com/exdietolog/robo_lab/tree/godot-4.1.1).

## Что установить

| Что | Версия | Где взять |

Проверьте SDK командой `dotnet --list-sdks`. Обычная сборка Godot без .NET проекты не откроет: C#-скрипты не будут найдены.

## Как открыть лабораторную

1. Запустите Godot и в менеджере проектов нажмите **Import**, выберите `project.godot`, оставьте флажок **Edit Now** и нажмите **Import** (например, `task_03/software_0b10/project.godot`).
2. Соберите C#-код: кнопка **Build Project** (молоток справа вверху) или **Alt+B**. При первой сборке пакеты Godot скачиваются с NuGet — нужен интернет. Ошибки сборки видны во вкладке **MSBuild** внизу.
3. **F5** — запуск главной сцены проекта, **F6** — запуск открытой сейчас сцены.

Без редактора: `godot --path task_03/software_0b10` (запуск) или `dotnet build "software 0b10.csproj"` в папке проекта (только сборка).

## Лабораторные работы

Все работы используют одного и того же робота — четырёхосевой манипулятор (поворот колонны `A`, плечо `B`, предплечье `C`, поворот фланца `D`). Положение фланца описывает структура `Pose4`: точка `translation` (м) и угол поворота вокруг вертикали `rotation` (градусы). Робот реализует интерфейс `IMechanism<Gen, Pos>`: прямая задача — `SolveForward`, обратная — `SolveInverse`.

### ЛР 1. Моделирование манипулятора, прямая и обратная задачи кинематики

Папка [`task_01`](task_01/), методичка [`Лаб_раб_1.pdf`](task_01/Лаб_раб_1.pdf), проект `software_0b00`.

- **Цель:** научиться собирать модель робота из готовых деталей и решать для неё задачи кинематики по положению.
- **Задание 1.** Собрать сцену `Prefab/Task/TaskRobot.tscn` из моделей `Resources/Models/Task/`, расставить узлы `Node3D` по размерам из методички, заполнить в инспекторе поля-ссылки скрипта `TaskRobot` и заставить модель двигаться при изменении `A`–`D` (метод `_Process`). Скрипт помечен `[Tool]`, поэтому проверять движение можно прямо в редакторе: пересобрать проект (Alt+B) и менять `A`–`D` в инспекторе.
- **Задание 2.** Прямая задача кинематики: `SolveForward` в `TaskRobot.cs`. Проверка — робот правильно держит объект `Hold` на сцене `TaskScene.tscn`.
- **Задание 3.** Обратная задача кинематики: `SolveInverse`. Проверка — робот следует за целью `TaskTarget` и поворачивает фланец вместе с ней.
- **Пример:** трёхосевой робот `Prefab/Sample/SampleRobot.cs` с готовыми решениями обеих задач — с него стоит начать. В шаблоне папка `Prefab/Task/` пуста: сцены и скрипты четырёхосевого робота создаются по методичке.

### ЛР 2. Команды движения манипулятора

Папка [`task_02`](task_02/), методичка [`Лаб_раб_2.pdf`](task_02/Лаб_раб_2.pdf), проект `software_0b01`.

- **Цель:** реализовать два вида движения: переброску (PTP, `Joint4`) — интерполяцию обобщённых координат, и линейное движение (LIN, `Linear4`) — интерполяцию положения фланца.
- **Задание 1.** Задать свою последовательность движений трёхосевого робота в `Prefab/Sample/SampleController.cs` (команды `Joint3` и `Linear3`).
- **Задание 2.** Перенести кинематику из ЛР 1 в `Prefab/Task/TaskRobot.cs` (места `// Fix here`), создать `TaskController.cs`, сцену `TaskScene.tscn` и команду `Code/Task/Joint4.cs`.
- **Задание 3.** Создать `Code/Task/Linear4.cs` и добавить линейные движения в `InitCommands`.
- Код `Joint4` / `Linear4` понадобится в ЛР 3.

### ЛР 3. Локальные системы координат инструмента и детали

Папка [`task_03`](task_03/), методичка [`Лаб_раб_3.pdf`](task_03/Лаб_раб_3.pdf), проект `software_0b10`.

- **Цель:** задавать движения не фланца, а рабочей точки инструмента (TCP), причём в системе координат детали.
- **Основная формула:** `F_flange = F_part × F_TCP,part × F_TCP,flange⁻¹`. В коде: `Combine` — умножение поз, `Inverse` — обратная поза (интерфейс `Frame<Pos>`).
- **Задание 1.** Дописать `Code/Command/Joint4.cs` (места помечены `(1.x)`): перенести переброску из ЛР 2 и пересчитывать начальную и целевую позу с учётом `tool` и `part`.
- **Задание 2.** То же для `Code/Command/Linear4.cs` (`(2.x)`); интерполируется положение TCP, а не фланца. Затем раскомментировать блок `(2.3)` в `Prefab/Task/TaskController.cs`.
- **Задание 3.** Составить свою программу движений относительно деталей `PartGreen` и `PartRed` (они уже стоят на сцене `Prefab/Task/TaskScene.tscn`; инструменты — красный и зелёный наконечники `DemoTool`).
- Пока заготовки пустые, робот стоит на месте, а сборка выдаёт 2 предупреждения о неиспользуемом поле `progress` — это нормально.

### ЛР 4. Управление манипулятором асинхронными функциями

Папка [`task_04`](task_04/), методичка [`Лаб_раб_4.pdf`](task_04/Лаб_раб_4.pdf), проект `software_0b11`.

- **Цель:** писать программу робота как обычный код с `await`, циклами и условиями, а не как заранее заполненную очередь команд.
- **Что есть в шаблоне:** готовые команды `Joint4` / `Linear4` / `WaitFor`, захват `Gripper`, два подающих конвейера `BoxSource` / `BoxSource2` (выдают коробку раз в 15 и 20 с) и демонстрационная функция `Run` в `Prefab/TaskController.cs`: робот берёт две коробки и ставит их стопкой.
- **Задание 1.** Переписать `Run` под задание преподавателя — уложить стопку коробок последовательным кодом (`PickBox` / `PlaceBox`).
- **Задание 2.** Повторяющиеся действия объединить в цикл.
- **Задание 3.** В цикле брать первую готовую коробку с любого конвейера: `await WaitFor(() => boxSource.BoxIsReady || boxSource2.BoxIsReady);`
- Ожидание коробок занимает много времени; ускорить симуляцию можно запуском `godot --path task_04/software_0b11 --time-scale 4`.

## Частые проблемы

- **«.NET Sdk not found» / скрипты не находятся** — запущена обычная сборка Godot или не установлен .NET SDK 8.0 (`dotnet --list-sdks`). Если раньше стоял 32-битный .NET, удалите его.
- **Сборка долго «висит» в первый раз** — скачиваются NuGet-пакеты Godot; нужен доступ к nuget.org.
- **После изменения `[Export]`-полей в C# они не появились в инспекторе** — пересоберите проект (Alt+B) и переоткройте сцену.
- **Linux / WSL без видеокарты** — Godot рисует на процессоре (llvmpipe), это медленно, но работает. Можно попробовать `--rendering-driver opengl3`.
